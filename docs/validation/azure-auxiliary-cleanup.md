# Azure shared Network Watcher cleanup

This optional cleanup path is disabled unless the exact `azure_auxiliary_cleanup` runtime binding and its `approval_refs.azure_shared_cleanup` card are present and approved. It is restricted to the exact Sweden Central subscription, watcher, and `NetworkWatcherRG` identities. The prepared cohort manifest binds both normal acceptance runtime paths and hashes (or the single CAL-S1 runtime), config and source hashes, parent manifests, and exact parent resource identities. The card binds that manifest and owner set, separate expected watcher-creation and owned-write callers, a finite UTC validity window, and caps of one watcher delete and one resource-group delete. Prepare emits the immutable scope manifest and card destination but does not create approval evidence; activation requires a separately reviewed approved card.

Normal S1/S3 cleanup waits for both Azure parents to prove their own VMs, resources, expiry support, and roles absent inside the existing routine cleanup deadlines. The earliest shared pre-creation baseline is durably recorded before provider mutations. A pre-existing watcher or group is never deleted. The path then requires complete pre-mutation inventories, one successful watcher creation event after baseline capture, a unique correlation to successful owned NIC and VM writes, empty flow log, packet capture, and connection monitor collections, plus fresh full inventories proving both parents absent immediately before each destructive action. It uses a fresh ETag with `If-Match` for the watcher delete, verifies the exact typed 404, then deletes the empty resource group without an ETag precondition because the retained Azure group readback contains no ETag.

The shared journal is lock-protected and one-shot. An uncertain leaf action is never retried. A durably recorded exact leaf 404 can resume at the group step; an interrupted or uncertain group delete remains failed. A missing peer, stale or changed card/source, changed inventory, deadline expiry, or incomplete Activity Log evidence leaves cleanup blocked. The default path and historical failed attempts are not changed. Focused fake tests establish local control flow only; they do not qualify Azure API semantics, permissions, or live deletion.
