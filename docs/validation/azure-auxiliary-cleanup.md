# Azure shared Network Watcher cleanup

This optional cleanup path is disabled unless the exact `azure_auxiliary_cleanup` runtime binding and its `approval_refs.azure_shared_cleanup` card are present and approved. It is restricted to the exact Sweden Central subscription, watcher, and `NetworkWatcherRG` identities. The card binds the runtime hash, both normal acceptance parent identities (or the single CAL-S1 parent), their config hashes and resource IDs, one expected Activity Log caller, a finite UTC validity window, and caps of one watcher delete and one resource-group delete.

Normal S1/S3 cleanup waits for both Azure parents to prove their own VMs, resources, expiry support, and roles absent inside the existing routine cleanup deadlines. The path then requires complete pre-mutation inventories, one successful watcher creation event after baseline capture, a unique correlation to successful owned NIC and VM writes, and empty flow log, packet capture, and connection monitor collections. It uses a fresh ETag with `If-Match` for the watcher delete, verifies the exact typed 404, inventories the empty parent group, then uses its fresh ETag with `If-Match` for the group delete. No provider delete is inferred from a baseline alone.

The shared journal is lock-protected and one-shot. An uncertain leaf action is never retried. A durably recorded exact leaf 404 can resume at the group step; an interrupted or uncertain group delete remains failed. A missing peer, stale or changed card/source, changed inventory, deadline expiry, or incomplete Activity Log evidence leaves cleanup blocked. The default path and historical failed attempts are not changed. Focused fake tests establish local control flow only; they do not qualify Azure API semantics, permissions, or live deletion.
