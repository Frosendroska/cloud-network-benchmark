# F05 AWS provider implementation

F05 adds an AWS-specific provider adapter with an isolated regional SSM Automation safety root and a separately applied two-VM topology root. `AwsProviderDriver.register_expiry` requires the active reservation and dated cost identity, registers and reads back a running absolute-time sleep in every involved region, and only then permits pair apply. Its 360-second trigger lead comprises a 300-second discovery/stop window and 60 seconds of planned margin. The Automation script re-queries for the entire bounded horizon using both run and deployment tags, records stop requests separately from observed states, and never deletes resources. A successful stop is compute expiry evidence, not cleanup completion. IAM propagation can be eventual: the role trust and scoped policy are created before start, registration requires a successful readback, and an uncertain start keeps that region's safety resources while blocking pair launch; there is no unbounded propagation wait or automatic retry that could duplicate an execution.

The public runtime entry points are `AwsProviderDriver.register_expiry`, `provision`, and `cleanup`, with settings supplied through `AwsRuntimeSettings`. The pair root selects two On-Demand Ubuntu 24.04 amd64 `m7i.xlarge` VMs, 32 GiB gp3 root volumes, fixed scenario-specific Frankfurt/London subnets and private benchmark ingress. The adapter revalidates the account, instance ownership tags, image owner/architecture, instance type, physical zone ID, placement group, addresses, root volume and console-authenticated ED25519 host key before creating strict attempt-local `known_hosts`. State, tfvars, command records and host trust files are private and isolated by run/deployment. A failed or unreadable attempt journal, residual resources, or uncertain inventory blocks another AWS attempt for that run. Cleanup attempts Terraform destroy, independently inventories tagged resources in every involved region, waits for compute absence before cancelling expiry, then destroys and API-verifies the regional document and role.

The scenario admission evidence and network values are supplied by the caller and must remain sourced; this adapter does not invent an S4 review or imply that a throughput ceiling is observed. The dated public SSM pricing fixture assumes no free tier and records $0.013 per regional two-step/300-second execution ($0.026 for two regions). Response fixtures preserve the SSM start execution ID, confirmed InProgress sleep step and absolute timestamp, and authenticated host console boot ID and ED25519 fingerprint. Failure fixtures name incomplete or inaccessible API states; none are AWS observations. The price is a planning input, not a billing guarantee. Expiry automation has startup, stop latency, and late-creation limits; later paid acceptance must verify the registered safety role and real resource behavior.
