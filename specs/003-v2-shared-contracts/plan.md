# Implementation Plan: F01R V2 shared contracts

**Branch**: `codex/f01r-v2-contracts` | **Date**: 2026-10-21 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/003-v2-shared-contracts/spec.md`

## Summary

Migrate the existing small Python contract/config/manifest/CLI foundation to one explicit V2
boundary. Preserve immutable path allocation, failure evidence and fake commands. Add only the
mode-aware native evidence, identity, provenance and safety DTOs required by dependent features.
Local validate/resolve/dry-run/init describe intent without launching resources. Preserve historical
specs/001 and specs/002. Public field names, invariants and ownership are in data-model.md and
contracts/shared-contracts.md; research.md records inspected evidence and engineering decisions.

## Technical Context

**Language/Version**: Existing Python ≥3.9 package; preserve its declared supported version.

**Primary Dependencies**: Existing Pydantic 2 and PyYAML 6; pytest 8/jsonschema test extras. No new
runtime dependency is needed. Local Git is used only for optional provenance through injection.

**Storage**: Local immutable results/raw directories, atomic JSON manifests and YAML/CSV snapshots;
no database, object store or remote state. Current V2 JSON schemas are versioned in this feature.

**Testing**: Existing unit/contract/integration pytest layout, temporary files/Git repositories,
scripted commands and explicit external-I/O denial; meaningful migration fixtures, no real traffic.

**Target Platform**: Local controller on macOS/Linux; Ubuntu 24.04 amd64 VM intent, not VM execution.

**Project Type**: Existing CLI/library contract migration, not a new service or app.

**Performance Goals**: Preserve existing practical config/initialization performance checks. Use
bounded fixtures and fake long-mode descriptions; never wait 24 hours or enumerate raw packets.

**Constraints**: No credentials/cloud calls, Terraform apply, real benchmark commands or paid
admission. No application runner/parser/collector/provider/scheduler implementation. Retain source
fixed settings and pending evidence. Exactly two roles per selected provider.

**Scale/Scope**: Four modes; S1–S4 with three explicit providers; four existing research configs,
two new retained-mode configs and existing four validation configs. Three user stories/24 FRs.

### Source Code (repository root)

```text

  contracts/{common,campaign,deployment,artifacts,validation,execution,__init__}.py
  contracts/admission.py        # new immutable schedule/reservation/expiry DTOs
  contracts/measurements.py     # new timing/diagnostic/metadata DTOs
  contracts/schema.py           # deterministic current-schema export/check module
  {config,ids,manifests,paths,lifecycle,dry_run,cli,errors}.py
configs/{README.md,experiments/*.yaml,tests/*.yaml}
tests/{unit,contract,integration,fixtures}/
docs/f01r-offline-validation.md
```

**Structure Decision**: Keep the current package and public names. New DTO modules remove actual
ownership gaps; do not introduce repositories, services, adapters registries or separate V2 package.
Current source ownership is limited to the files above and narrowly required matching fixture/test
updates. `access.py`, `bootstrap.py`, `readiness.py`, `retrieval.py`, Terraform/templates, README
runtime instructions and historical specs are outside F01R; an unavoidable compatibility edit
requires an explicit scoped amendment before implementation. Most F02 tests only need updated DTO
fixtures. Existing F02 runtime behavior is not V2 readiness and is migrated by F02R.

## Design and delivery phases

1. Phase 0 research completed locally: code inspection and D01–D08 in research.md; no unresolved
   F01R engineering choice or source conflict.
2. Phase 1 design completed: data-model.md defines public shape and invariants;
   contracts/shared-contracts.md defines functions, modes, native layout and dependent ownership;
   quickstart.md defines exact acceptance commands and known baseline failures.
3. Implementation proceeds in tasks.md story order after common types. US1 is independently checked through the config library and temporary fixture callers; existing CLI/rendering updates close in US3. Avoid new import-time dependence from the config loader onto unfinished manifest/CLI/schema implementations. US1 resolves all configs;
   US2 allocates traceable local attempts; US3 publishes downstream handoffs/schema and CLI proof.
   Shared files are edited sequentially by one writer. Test-only work in independent files can be
   parallel in principle, but this assignment uses one implementer and no subdelegation.
4. Spec Kit convergence and the full appropriate offline suite must pass at the exact delivery
   head. Coordinator serializes merge before any dependent branch consumes these contracts.

## Complexity Tracking

No constitution violation or complexity exception. No new runtime framework/dependency or parallel
legacy engine. Calibration selection calculations, native parsing, live expiry and admission logic
are deliberately absent; only their explicit input/output records are delivered.
