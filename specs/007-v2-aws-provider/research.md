## Independent expiry without known VM IDs

**Decision**: Use a per-attempt custom SSM Automation document (`schemaVersion: 0.3`, type Automation) and service role. Start one execution per involved region before VM creation. Two steps only: `aws:sleep` with absolute UTC `Timestamp`, then an inline Python 3.11 `aws:executeScript` that queries EC2 by exact attempt tags and stops matching instances. No guest SSM agent, instance profile, Scheduler, Lambda, queue, storage or telemetry is needed. The narrow AWS-hosted stop script is the constitution's authorized expiry exception, not a framework service.

**Rationale**: AWS documents absolute-time sleep up to 604799 seconds, covering the selected 87600-second maximum cap. The later script can discover IDs that did not exist at registration. A service role permits EC2 API use without the controller. API script actions support a maximum 600 seconds and require explicit throttling handling. [Sleep](https://docs.aws.amazon.com/systems-manager/latest/userguide/automation-action-sleep.html), [script action](https://docs.aws.amazon.com/systems-manager/latest/userguide/automation-action-executeScript.html), [runbook role semantics](https://docs.aws.amazon.com/systems-manager/latest/userguide/automation-document-script-considerations.html).

**Alternatives considered**: Guest shutdown fails independence. Registering StopInstances with IDs after creation fails required ordering. An EventBridge universal target cannot itself discover unknown IDs; pairing it with Automation adds an unnecessary resource. A tag-targeted managed runbook resolves targets when execution begins, before the pair exists, unless a separate scheduler is added. Maintenance Windows risk managed-node selection/agent coupling. An inline Automation discovery step is the smallest selected complete mechanism.

## Registration, deadline and late creation

**Decision**: Separate safety-only Terraform root from the pair root. Safety root creates only IAM/document resources, after supplied reservation activation. Explicit AWS CLI calls through CommandRunner start/read back Automation; nothing launches VM creation as a Terraform provisioner. Aggregate registered evidence is emitted only after every regional execution is confirmed. Persist deterministic UUID client tokens and execution IDs privately before proceeding, allowing readback/recovery of ambiguous starts without blind duplicate execution.

Readback uses `GetAutomationExecution.AutomationExecution`: exact ID/document/version/parameters, `AutomationExecutionStatus=InProgress`, `CurrentAction=aws:sleep`, `CurrentStepName=waitUntilExpiry`, and matching `StepExecutions` action/inputs. Accept only a future matching Timestamp and observed running sleep. Poll pending states within one absolute registration deadline; statuses outside the confirmed predicate never authorize creation. This strict predicate may reject a valid-but-ambiguous response safely. Do not invent an API field named registered/waiting; those are local meanings only. [Start](https://docs.aws.amazon.com/systems-manager/latest/APIReference/API_StartAutomationExecution.html), [Get](https://docs.aws.amazon.com/systems-manager/latest/APIReference/API_GetAutomationExecution.html), [execution fields/statuses](https://docs.aws.amazon.com/systems-manager/latest/APIReference/API_AutomationExecution.html), [step fields](https://docs.aws.amazon.com/systems-manager/latest/APIReference/API_StepExecution.html).

Reservation activation immediately before safety side effects is cap start. Use the supplied cap endpoint unchanged. Engineering safety lead is 360 seconds within that cap: expiry trigger at cap end minus 360 seconds, script bounded to 300 seconds, leaving 60 seconds planned stop margin. This is an engineering allowance, not another result-copy timer or a cap increase. Reject registration/provisioning if setup, specified measurement, retrieval and cleanup cannot fit before the earlier trigger. Map trigger to ExpiryEvidence.expires_at; retain script deadline and reserved cap end separately in provider_metadata. A cap cannot be reset on recovery or region registration. Keep clock injection private to this feature, with no new shared timing fields.

At expiry paginate DescribeInstances filters for exact `cnb_run_id` AND `cnb_deployment_id` (all instances tagged atomically on RunInstances). Filter region/account through client/role scope. Requery every five seconds for the full 300-second discovery horizon even when initially empty; pending instances may become stoppable later. Stop only matching running instances; retry pending/IncorrectInstanceState and transient throttling/service errors within the same horizon, with bounded API timeouts. Track every seen ID/state and errors. Never stop an unfiltered account or assume an empty first page is final. More than two matches is an integrity failure but stop all owned matches to limit leakage and report the anomaly. Final observed pending/running/stopping or denied discovery remains unresolved. Stop defaults remain graceful; no forced stop or deletion fallback is silently introduced.

EC2 has eventual consistency and stop requests are asynchronous. An in-flight creation may become visible late or after the script horizon; stop can exceed the planned margin during provider failures. No absolute billing or stop-time guarantee is claimed. Record trigger, requests, observed stopped states, failure/late IDs and residual resources. Planned admission reserves the complete cap and expiry charges, but any actual overrun remains incurred-cost evidence and a launch blocker, not silently forgiven. [DescribeInstances](https://docs.aws.amazon.com/AWSEC2/latest/APIReference/API_DescribeInstances.html), [StopInstances](https://docs.aws.amazon.com/AWSEC2/latest/APIReference/API_StopInstances.html).

## Permissions, cost and cancellation

**Decision**: Safety Terraform owns one attempt-specific Automation role with trust for `ssm.amazonaws.com`, scoped account/source safeguards where supported, EC2 DescribeInstances read access and StopInstances restricted by region/account and BOTH exact ownership tags. Controller needs explicit IAM role/policy create/delete/read and PassRole restricted to that role/SSM; SSM document create/delete/get, Start/Get/Describe/StopAutomationExecution; EC2 network/instance/volume/address/keypair/peering/placement lifecycle and read/console/image/type/zone permissions. Document/role setup and propagation/readback failure blocks VM creation. No VM role or guest agent. Fixtures assert least-scope write permissions; read-only inventory APIs that require Resource `*` are documented.

Identified price input `aws-ssm-automation-public-2026-10-22` records the published USD $0.002/step and $0.00003/script-second as checked on this date, not a live execution quote or assumed free tier. Maximum planned two-step, 300-second execution costs $0.013/region, $0.026 for S4 before tax/uncertainty and separately accounted compute/disks/public IPv4/transfer. No attachments or logs are configured. Hash the input fixture; reject reservation cost evidence that excludes the expiry allowance. Refresh all prices and actual policy/quota readiness before separate paid execution. [Official Automation pricing](https://aws.amazon.com/systems-manager/pricing/).

After verified VM absence, cancel still-running execution with StopAutomationExecution Type=Cancel and read back terminal cancellation. If already completed, preserve actual success/failure rather than relabel it cancelled. Empty HTTP success is not cancellation proof. Remove safety root only after execution is terminal and compute absent; on uncertainty retain role/document and recovery evidence. [Cancellation API](https://docs.aws.amazon.com/systems-manager/latest/APIReference/API_StopAutomationExecution.html).

## Topology, identity and evidence

**Decision**: One pair root with explicit Frankfurt and London provider aliases, scenario-controlled resources and no module platform. S1/S3 private addresses A `10.60.1.10`, B `10.60.1.11`; S2 B `10.60.2.10`; S4 B `10.61.1.10`. Public management uses auto-assigned public IPv4 (not EIPs). Separate VPCs make concurrent attempts with same selected CIDRs independent. S4 peering requires requester plus London accepter and reciprocal routes; destroy requester and verify both views, since deleting accepter management alone does not delete peering. [HashiCorp peering resource](https://raw.githubusercontent.com/hashicorp/terraform-provider-aws/main/website/docs/r/vpc_peering_connection_accepter.html.markdown).

Require explicitly selected regional Canonical AMI IDs; verify owner `099720109477`, Ubuntu noble 24.04 amd64/HVM and ENA via provider-authenticated DescribeImages, recording exact identities. No newest-image drift or software approval gate is introduced. Use normal checked-in provider lock selected by implementation from current supported HashiCorp AWS 6.x; Terraform 1.16.6 is available locally. Instance attributes use gp3/delete_on_termination, explicit zones, one NIC, default On-Demand (omit Spot market options), metadata IMDSv2, ENA capability and disabled ENA Express/EFA. Do not set an unsupported Terraform `ena_support` instance argument; verify supported schema and image/instance evidence. [Current instance docs](https://raw.githubusercontent.com/hashicorp/terraform-provider-aws/main/website/docs/r/instance.html.markdown), [document resource](https://raw.githubusercontent.com/hashicorp/terraform-provider-aws/main/website/docs/r/ssm_document.html.markdown).

Host trust uses authenticated GetConsoleOutput bound to account/region/instance and current boot, with cloud-init publishing public host-key fingerprints. Obtain a candidate ED25519 public key via keyscan through injected command boundary, compare its SHA256 fingerprint to authenticated console evidence, then write strict known_hosts. Keypair authentication fingerprints are different and cannot establish host identity. Missing/multiple/conflicting/stale console keys fail closed. [AWS host fingerprint procedure](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/connection-prereqs-general.html).

Documented network evidence retains 1.562 Gbit/s baseline and up-to-12.5 Gbit/s burst from the canonical design, dated/source-labeled and distinct from observed results. Real DescribeInstanceTypes metadata can confirm differences; never replace observations with documentation. Provider output conveys intended MTU/CC/security and actual provider facts; F02R/F04 later verify guest settings through their existing boundary. F05 does not import unfinished siblings or claim offline fixtures prove AWS behavior.
