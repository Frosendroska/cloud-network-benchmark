# GCP provider boundary

Frozen shared imports: `contracts.deployment.{ProviderDeploymentInput,ProviderDeploymentOutput,ProviderVmOutput,RemoteConnectionData}`, `contracts.admission.{ExpiryRequest,ExpiryEvidence,ReservationEvidence}`, `contracts.common.{CleanupState,FailureEvidence,Evidence,StructuredEvidence}`, `contracts.execution.{CommandRunner,CommandRequest,CommandResult}`. GCP provider_options STOP requires the coordinator's F01R_GCP_EXPIRY merge first. No shared CleanupEvidence exists.

## Python API

`GcpProviderDriver(runner: CommandRunner, settings: GcpRuntimeSettings, clock=...)` in `src/cloud_network_benchmark/providers/gcp.py`; ordinary provider-local helpers, no generic orchestration abstraction.

- `register_expiry(deployment: ProviderDeploymentInput, request: ExpiryRequest) -> ExpiryEvidence`: require original active reservation, matching identity, governing STANDARD/STOP, dated cost coverage, no open cleanup, original cap/T and full remaining workflow fit. Invoke protection root only, wait bounded completion, authenticate/read back both immutable templates and record private bindings. Return registered only when both are observed; failed/uncertain registration preserves available IDs/operations, never invokes pair, and cleans unused protection where safe. A provider-local exception may preserve equivalent evidence.
- `provision(deployment: ProviderDeploymentInput) -> ProviderDeploymentOutput`: require matching registered evidence and journal. Immediately recheck exact templates, unique IDs/properties/T and workflow fit; reject DELETE, relative duration, overrides or missing protection. Journal creation-may-have-started before pair command. Apply pair, normalize Terraform plus authenticated GCP readback, verify actual scheduling/selection, acquire authenticated host keys and export redacted output. Failure preserves partial evidence and attempts cleanup once creation may have started.
- `cleanup(deployment: ProviderDeploymentInput) -> GcpCleanupResult`: use original two state roots/journal; destroy pair, verify owned compute absent across all zones, then remove protection/support and verify all owned resources absent. Partial destroy/denied inventory/pagination failure/residuals remain failed/open, preserving primary and cleanup errors. Repeated calls do not recreate resources or reset cap. Cancellation never disables inherited expiry on a live VM.

Caller supplies exact runtime settings and admitted evidence. The driver validates these supplied decisions; F11's budget accounting and F09's lifecycle/retained modes are separate. For S2/S4 require sourced explicit review/admission even when the existing acceptance requires_primary_review flag is false, so merely selecting optional acceptance cannot authorize paid execution. No F07 CLI addition or import from unmerged siblings.

## Terraform API

Protection inputs: project, fixed role names/zones/subnets/private addresses, namespace/full identity metadata, exact image IDs, controller /32, attempt public key, supplied preparation content, absolute T/STOP, selected scenario and bounded timeouts. It creates one custom VPC (MTU1460), selected subnets/firewall rules, S3-only compact resource policy, and two global instance templates. It contains zero standalone VMs, actual boot disks, reserved addresses, instance groups, provisioners or scheduling services. Templates describe future boot disks/ephemeral public IPv4 and do not materialize them.

Protection outputs: both template numeric IDs/unique self links and properties, VPC/subnet/firewall/optional placement IDs. Driver authenticates API readback rather than trusting Terraform output alone. Each template includes exactly one 32-GiB pd-balanced boot disk, exact Ubuntu image, n2-standard-4, one GVNIC/no Tier_1, role-specific private IPv4 and ephemeral management accessConfig, STANDARD, automatic_restart=false, absolute termination_time=T, instance_termination_action=STOP. S3 resource_policies holds only its COLLOCATED policy with no max_distance. Other scenarios have no placement resource policy. Supplied preparation data is not claimed as guest observation.

Pair inputs: verified role->source_instance_template unique link, exact names/project/zones and timeouts. Pair contains exactly two `google_compute_instance_from_template` resources and no overrides of scheduling, network, disks, metadata, labels, machine/image or placement. It has no data source that reselects a mutable template by name and no remote state dependency. Outputs: observed VM IDs/addresses/disks plus ordinary provider properties. Driver retains actual creation binding/config evidence and checks instances.get; it does not require a fabricated sourceInstanceTemplate response attribute.

State directories are private, separate under one attempt root, with no backend/remote-exec/local-exec. Committed .terraform.lock.hcl per root pins actual schema-selected Google version; downloaded providers/vars/state/plans remain ignored and private. Static checks must reject accidental extra resources and weakening overrides, not merely search for two strings.

## GCP API, trust and cleanup

All Terraform/gcloud/ssh-keygen invocations are shell-free CommandRequests with explicit assigned cwd/action ID/deadline/redactions. Pass explicit project/zone/region and use a private credential reference, never export credential values. Bounded gcloud commands use JSON describing documented REST objects: templates describe, instances describe/get-guest-attributes, and owned inventory. Terraform operations are fake in tests. No API enabling or IAM grants occur here.

Host trust uses authenticated instances.get and `instances.getGuestAttributes(queryPath=hostkeys/)`, matching the role/project/zone/numeric VM ID before and after retrieval. Parse documented queryValue.items namespace/key/value; validate public-key format and populate private known_hosts for actual management host. Missing/stale/mismatched evidence fails trust. Guest-agent evidence is not hardware attestation. Existing F02R subsequently performs strict SSH; this provider never trusts an unauthenticated keyscan as proof.

Inventory covers exact known IDs and attempt-scoped paginated discovery: instances in both relevant regions/zones, disks including auto-delete boot disks, networkInterfaces/accessConfigs and reserved regional/global addresses if found, firewall rules, subnets, VPC/generated routes, S3 resource policy and both templates. Check ownership before deletion and preserve foreign matches. Authenticated not-found for the expected project/ID can prove absence; permission errors, list warnings, unreachable scopes, unknown operations and unfinished pages cannot. Ephemeral public address disappearance follows verified VM/accessConfig absence; zero reserved-address resources in intended Terraform is not enough to ignore a discovered leftover.
